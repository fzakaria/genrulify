Any Nix build, as genrules. A build recorded by Rewind is cut wherever the builder calls execve. Every file a process group writes becomes an SSA value in an MLIR dialect, dead processes are eliminated, each survivor is replayed alone against the recording, and what is left is lowered to one genrule per group. There are no rules for C or autotools here. Nix, Bazel and Buck2 produce the same NAR.

Reading this page

A cut starts where the builder, or a subshell it forked, calls execve. Cuts that share a pipe or ran at the same time form a group. The filesystem is snapshotted before and after each group, and the difference is what the group wrote.

A group is replayed when running it alone in a sandbox, given only its recorded inputs, leaves files with the recorded hashes. A group that needs more than the files it opened is replayed once under a system call tracer and then given exactly the files, directories and listings the trace shows it touching. A group that cannot be reproduced, such as mktemp, is kept as recorded bytes. A group is dead when no output depends on anything it wrote.

The graph recomputes the build that was recorded. It is not an incremental build for edited sources: change an input and the recording no longer describes the build.

Why a graph in which every node passed its replay check has to produce the recorded output, under any scheduler, is written up in the theory behind the genrules.
