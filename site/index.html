Any Nix build, as genrules. A build recorded by Rewind is cut at every command it ran. Each command becomes one build rule that runs the command line that was recorded, on the files the command read. A compile reads as cc_object and a link as cc_binary, but nothing here knows how to build C: the rules come from what happened. Nix, Bazel and Buck2 produce the same NAR.

    Reading this page

    A cut starts where the builder, or a subshell it forked, calls execve. Cuts that share a pipe or ran at the same time form a group. The filesystem is snapshotted before and after each group, and the difference is what the group wrote.

    A group is replayed when running it alone in a sandbox, given only its recorded inputs, leaves files with the recorded hashes. A group that needs more than the files it opened is replayed once under a system call tracer and then given exactly the files, directories and listings the trace shows it touching. A file that differs on every run, such as a log with a timestamp in it, is pinned: the group still runs, and that one file is taken from the recording. A group is kept as recorded bytes when it cannot be reproduced at all, or when the only thing of it that a later step reads is pinned. hello's make check is one: the install step looks at its test log and at nothing else it wrote, so the tests do not run again. A group is dead when no output depends on anything it wrote.

    Three passes then remove work that computes nothing. A group is folded to constants when all a later step reads of it is directories, symlinks or empty files, and raised to copies when every file a later step reads of it has the bytes of a file it was given. Neither runs in the generated build. Each rewrite leaves every file version with its recorded bytes, which is all the proof needs.

    A rule's cmd is the recorded command line, handed to sandbox.sh, a shell script that ships in the generated workspace. The script puts the rule's inputs back at the paths the command saw, runs the command, and fails the rule unless every output has the recorded hash. The BUILD.bazel and BUCK tabs show the rule for whichever node is selected.

    The graph recomputes the build that was recorded. It is not an incremental build for edited sources: change an input and the recording no longer describes the build.

    Why a graph in which every node passed its replay check has to produce the recorded output, under any scheduler, is written up in the theory behind the genrules.
