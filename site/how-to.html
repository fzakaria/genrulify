How to use it?

To record a build, you need Nix with flakes enabled, an x86-64 Linux machine with access to KVM, and Rewind on your PATH. To build the generated rules, use Bazel or Buck2 on a machine with bubblewrap and the Nix store paths from the recording.

Rebuild a Nix package

convert records the Nix build of GNU hello and writes Bazel and Buck2 rules in hello/workspace. To check a step such as compiling hello.c, it runs the compiler again in a sandbox with the inputs GCC used. It checks that GCC exits with the same status and produces the same object file. If a step cannot reproduce a file the build needs, the generated workspace can supply that file from the recording. 

nix run github:fzakaria/genrulify -- convert nixpkgs#hello hello
cd hello/workspace

Build the archive target with either tool. The result is a Nix archive (NAR) of the package. Its SHA-256 digest must match the one convert printed for the Nix output. A different digest means the build produced a different archive.

Bazel

bazel build //:archive
sha256sum bazel-bin/archive.nar

Buck2

buck2 build //:archive --out hello.nar
sha256sum hello.nar

Explore the recorded hello build.

Build from sources you can edit

The repository includes a small C project. Its Makefile compiles main.c and greet.c, then links the two objects. The .#project derivation uses examples/project as its source directory. Run these commands from the root of a genrulify checkout. 

nix run . -- convert --source examples/project .#project /tmp/project-recording
cd examples/project
bazel build //:archive

--source tells genrulify where the working sources live. It checks that they match the derivation's source, then writes BUILD.bazel and BUCK beside them. The rules read files from your checkout. Their scripts and manifests live under genrulify/. The last argument names a new directory for the recording and graph.

Change the greeting in greet.c and run bazel build //:archive again, or use buck2 build //:archive for both builds. The same compile command reads your edited file. The linker uses the new greet.o and the existing main.o. The rebuilt program now prints your new greeting.

The generated rules list the files and commands from the build you recorded. If greet.c starts including a new header, its compile rule needs that header as an input. If you add extra.c to the Makefile, the build needs another compile rule. In either case, rerun convert --source from the repository root to regenerate the rules. Give the new recording its own directory, for example /tmp/project-recording-2.
