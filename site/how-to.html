How to use it?

To record a build, you need Nix with flakes enabled, an x86-64 Linux machine with access to KVM, and Rewind on your PATH. To build the generated rules, use Bazel or Buck2 on a machine with bubblewrap and the Nix store paths from the recording.

Rebuild a Nix package

This command records GNU hello, checks which commands it can replay, and writes a Bazel and Buck2 workspace in a new directory called hello/workspace. 

nix run github:fzakaria/genrulify -- convert nixpkgs#hello hello
cd hello/workspace

Build the archive target with either tool. The result is a Nix archive (NAR) of the package. Compare its SHA-256 digest with the one convert printed for the Nix output. They should match.

Bazel

bazel build //:archive
sha256sum bazel-bin/archive.nar

Buck2

buck2 build //:archive --out hello.nar
sha256sum hello.nar

Explore the recorded hello build.

Build from sources you can edit

The repository includes a small C project. Its Makefile compiles main.c and greet.c, then links the two objects. The .#project derivation uses examples/project as its source directory. Run these commands from the root of a genrulify checkout. 

nix run . -- convert --source examples/project .#project /tmp/project-recording
cd examples/project
bazel build //:archive

--source tells genrulify where the working sources live. It checks that they match the derivation's source, then writes BUILD.bazel and BUCK beside them. The rules read files from your checkout. Their scripts and manifests live under genrulify/. The last argument names a new directory for the recording and graph.

Change the greeting in greet.c and run bazel build //:archive again, or use buck2 build //:archive for both builds. The build recompiles greet.c and relinks the program. It reuses the object for main.c.

Project rules accept changed output bytes. Their inputs and commands still come from the recording. If you add a source file or include a new header, run the conversion again from the repository root with a fresh recording directory.
